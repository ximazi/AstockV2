# 连续生命周期与换手率观察（v2.12.0）

## 本次修正

过去的日报与单股界面会把当天资金影子阶段、旧版阶段和当日量价分类当作
同一个“生命周期”。当日的吸筹形态可能覆盖此前启动记录。

现在分开三个字段：

- 发现路径：埋伏、点火、扩散，解释为什么入池。
- 连续生命周期：保留一轮行情的启动、上涨、整理、风险、失效和修复。
- 当日量价形态：当天观察结果，可以变化，但不重置一轮行情。

v2.12.0 在其下增加独立的回踩/平台子记录，以及速度和供需观察。不改生产引擎转移或买卖权限。

## 连续性约束

1. 启动后若当天变为吸筹或过渡形态，记录“启动后整理”，沿用本轮编号及启动日。
2. 跌破冻结的本轮结构底线，或原有上涨转为下跌结构，记录失效及原因。
3. 派发风险不会因次日没有新警告而自动消失，须需求恢复并收复对应压力位。
4. 失效后等待新的结构窗口及突破，才开启新一轮，不复活上一轮编号。
5. 今日落选不删除跟踪。候选集合与此前跟踪集合合并；缺数据标注 MISSING/STALE。
6. 按截至指定日的行情和生产轨迹重放。后来的行情不改写此前日期的判断。
7. 同一日期重复运行更新同一份日报，不额外制造一轮行情。

`cycle_id` 在首次观察到启动时建立，启动前的准备记录保留在时间线中。
`cycle_started_at` 是首次识别日期，不保证等于行情客观起点。
历史不完整时无法推断更早的轮次；`history_from` 表示可用行情起点。

## 换手率口径

- `turnover_pct`：行情源换手率，单位为百分数，沿用现有流通股口径。
- `turnover_relative20`：当日换手率 / 前20日换手率中位数，不含当日。
- `turnover_percentile120`：相对前120日有效换手率的分位，平值使用中间秩。
- `turnover_contraction5`：最近5日换手中位数 / 更早20日换手中位数。
- `turnover_down_up20`：最近20日下跌日 / 上涨日换手中位数，双方至少3个样本。
- `turnover_context`：分阶段解释活跃、承接待验证、启动后缩量或高位分歧。

0、负数、缺值不视为“极低换手”；样本不足显示数据不足。
每只股票先比较自身历史，不使用全市场固定的10%/20%阈值。
尚未加入板块、市值分组的历史校准；不能把当前自适应基线当作已完成该研究。
换手率只描述交易活跃程度，不证明机构吸筹、资金净流入或筹码集中。

## 验证与交易边界

连续阶段及换手解释是 `UNVALIDATED_OBSERVATION`。
重建窗口20交易日、相对换手1.3倍、收缩0.7倍等均为占位待校准，
沿用既有结构或量价观察尺度，不宣称具有新增交易预测能力。

价格重建启动标注 `PRICE_RECONSTRUCTION`，不能用来计算生产提前命中。
只有有日期的 `TRIGGERED` 记录才填入 `production_trigger_at`。
新增观察不授予买入许可，也不改生产 ARMED/READY/TRIGGERED 状态转移。
候选价值层只用已记录的生产触发历史防止重标为早期买点；行情陈旧时拒绝当前买点判断。

## 每日使用

原来的 `daily_full.ps1` 不需要增加命令，三方向报告内部自动更新。

只刷新现有数据的报告侧（不会重新跑反向溯源或生产扫描）：

```powershell
python -m mainwave_engine.three_direction_report --date 2026-09-04
python -m mainwave_engine.stock_analyzer --symbol 002903 --date 2026-09-04
```

输出目录 `results/mainwave_engine/YYYYMMDD/`：

- `stock_lifecycle.csv`：全部跟踪标的当日快照，包含今日落选标的。
- `stock_lifecycle_events.csv`：各标的可用历史中的阶段变更及理由，重建来源显式标注。
- `stock_lifecycle.md`：连续跟踪总表。
- `mainwave_weekly_candidates.md`：连续阶段、启动日期、相对换手和当日形态。
- `price_cycle_setups.csv`：各轮首次可知的回踩/平台、冻结边界、确认、失效和过期记录。
- `stock_analysis_*.json`：单股完整可用时间线；可视化逐日表与K线显示窗口一致。

本模块仅做轻量量价重放，不调用逐题材重型特征审计。
测试命令：`python -m unittest discover -s mainwave_engine -p "test_*.py"`。

## 回踩与平台

`cycle_id` 是父周期，`setup_id` 是其中的独立子记录。

- 已有推进之后才观察价格回踩或时间整理；不把每次触碰EMA都称为首次回踩。
- `FIRST_PULLBACK`：本轮可知启动后的第一次有效调整；失败也占用第一次身份。
- `LATER_PULLBACK`：同轮后续调整；新子记录还要有新的价格推进。
- `PULLBACK_UNKNOWN`：首次看到时趋势已经存在，不能确认是不是首次调整。
- `BASE_BREAK`：推进后的窄幅平台整理，和价格回踩分开记录。
- `FORMING -> CONFIRMED / FAILED / EXPIRED`。确认只出现一次，之后为 `HISTORY_*`，不重复发信号。
- 形成时冻结确认线、失效线与ATR；不因后续下跌放宽失效线。
- 父周期失效时，活动子形态也失效。子形态本身不能重置或解除父周期风险。

所有日期均为当日可知时间。`setup_adjustment_from` 是已观察到的调整起始日，
不代表当时已识别该形态；真正的可用日期是 `setup_started_at`。
图表中的冻结价转换到该张图的统一复权尺度，不等于历史当日原始成交价。

首版占位尺度：已有推进至少1个ATR，回踩位移0.8个ATR且至少2日后初步企稳；
平台至少5日、区间不超过2.5个ATR；子形态超过20个有效交易日过期。
确认还需收复冻结价格、收盘强度和换手需求恢复。缺换手不确认。
这些是研究定义，不是已验证的最优参数或交易规则。

## 上下行不对称

比较不重叠的前后两个5日价格速度，使用两段开始前已知的同一ATR归一化。
分别标记上涨加速、快速上涨、上涨减速、快速下跌、下跌减速等。

- 不预设每轮行情都必须走完“慢、快、极快”或“极快、慢、极慢”。
- 加速需要结合高换手价格受阻等证据看风险，不能仅因涨得快判顶。
- 下跌减速仅说明卖压推进减慢，不等于承接恢复，更不自动解除失效状态。
- 换手先相对个股自身历史比较；尚未做板块/市值分组校准。

## 历史案例入口

构建近一年案例库（按需执行，不加入每日全量任务）：

```powershell
python -m mainwave_engine.historical_cases --date 2026-09-04
python mainwave_visual_app.py --port 8070
```

浏览器访问 `http://127.0.0.1:8070/`，左侧有“每日候选”和“历史案例”两个独立入口。
历史列表支持闭合周期与启动失败筛选；K线阶段背景开关不影响均线或风险参考线。
“回踩与整理”表展示首次可知日、确认日、结束日和冻结边界。
如果端口已占用，使用另一个空闲端口。旧的分析台进程需重启才能载入新版代码。

输出位于 `results/mainwave_engine/historical_cases/`：

- `README.md`：案例清单及选择规则。
- `manifest.json`：范围、扫描股票、缺数据、版本及案例索引。
- 每案例一个JSON：价格、连续阶段、子形态与观察证据。页面读取缓存，不触发历史扫描。
- `verification.json`：逐例历史截面重算、图表覆盖和因果一致性检查。

首轮截至2026-09-04，扫描用户讨论股票加全域等距样本共130只（排除指数文件），
98个周期符合规则，展示8个闭合周期和3个失败对照。不是全市场发现率。
闭合周期要求观测启动、至少5日上涨延续、整理、结构失效及其后修复；
不要求盈利，也不强行补齐没发生的过热或派发阶段。

案例选取使用事后结果，但各日标签只用截至当日的数据。
历史重建不引入今日可变的资金事件存储或当前收益校准，不生成历史买卖许可。
没有当年生产证据的准备期不补画“资金吸筹”。题材/公司当前分类仅作导航。
行情更正后应重建案例库；历史案例冻结到构建时的数据，不是实时数据监控。

本次33个真实历史截面通过一致性检查，6个子形态中4个形态确认、2个形态失效。
这里的确认不是盈利，不能解释成66.7%交易胜率；新增策略的收益有效性尚未验证。
