# AI辅助复盘 V2：数据、提示词、接口与预算

## 1. 三种包不要混为一谈

|对象|内容|用途|
|---|---|---|
|原始证据层|全量行情、公告、逐笔、原计划/委托/成交；只追加版本|计算与追溯，不默认发送AI|
|AI精简证据包|必要统计、候选特征、原计划、反证、争议、源索引、有界取数需求|交给模型做解释、比较与补证|
|报告展示包|通过审核的结论、表格、图表、模式/状态、来源与可选全文|生成精华/细化HTML；可能比AI包大，绝不能直接当提示词|

目录中的data/report.example.json为第三类；prepare_ai_packet.py会生成第二类。不要把HTML、11份原文及重复的report.md/json/csv一并发给模型。

## 2. 本地先完成的任务

1. 完整读取，记录行数、证券覆盖、唯一键、源文件哈希、日期与真实可得时间。摘要截断不能代替全量读取。
2. 证券规则与时点统一。原始价、公司行动和复权价分字段；交易状态、合法价格范围、交易日历从有效版本读取。
3. 计算母池、市场/题材统计、连续过程和尾部。保留分母、排除项、参考周期、阈值版本，未知不补0。
4. 按原交易模式计算可观察事件：突破、回踩、重新转强、开板/回封、价格超限、逻辑失效。日线与分钟/逐笔精度不同；不补造事件先后。
5. 计算同类比较与风险：同板块/同波动/同任务表现、量能与价格进展、支撑/失效距离、预算状态、证据缺口。
6. 找回所有未结束计划与指定股，和今日状态做差分；不再每天换池遗忘昨天。
7. 分主题/模式保留候选，必保留集合不受Top-N限制。预算不足则分批。
8. 把正反证一起压缩，剩余数据留本地，模型只按需取窗口。

## 3. 最少字段与指标定义

### P0：所有重要候选共享的字段

- 股票、交易板块、交易日、快照时刻、数据可得时刻、映射/规则/模式版本。
- 用户任务、原跟踪理由、原计划/入场方式、预期持有期限、允许风险范围。未知不要代填。
- 开高低收、前收、成交量与金额单位、复权信息；足够历史窗口及有效行数。
- 1/3/5/20日表现；同类基准名称、成员版本、分位/排名、分母、适用周期。
- 相对换手/相对成交、自身历史分布、价格推进与收盘位置。
- 结构事件时间及可得时间、支撑与失效来源、未满足条件、下一复核。
- 重大公告/风险、公司行动或统计冲突；账户风险摘要和授权状态，不发送密钥。

日期收益率比较统一为相同复权和区间。原始涨幅排名与风险调整比较明确区分；不能把20%板块与10%板块的涨幅数字直接变成统一机会排名。

建议的新增研究特征：

- 同周期超额表现：r_i,h − r_peer,h，必须写清基准如何构成。
- 自身波动归一化：价格变化 / 当时已知ATR，必须记录ATR周期与方法。
- 失效距离：(计划入场价 − 结构失效价) / 入场价；压力损失另算。
- 盘中相对量：累计量 / 历史相同时点累计量基准，不与全天量比混用。
- VWAP：累计成交金额 / 累计成交股数。源量为手时先统一单位；不能把收盘价代替盘中均价。
- 收盘位置：(C−L)/(H−L)，H=L为不可定义，不填0。
- 日内后手价格表现：C/O−1；最高到收盘回落：C/H−1。都是价格路径统计，不等于策略可实现收益。

这些新增特征不是已验证交易阈值。不存在一个适用于全部模式的固定ATR、换手或涨幅否决值。

### P1：按模式追加

强势确认：开盘状态、关键价突破、分歧与修复、同行同时点响应、封板/开板/回封记录；需要逐笔/盘口的判断不能用分钟线冒充。

趋势回踩：冻结平台/均线来源、回踩段、缩量口径、确认事件、失效与退出；不能让所有其他模式都等同一回踩。

尾盘隔夜：14:30后原快照、原八步、分时新高后回踩顺序、下一交易日时间退出和封板例外版本。

### P2：事后评价

原始前向推荐/计划冻结记录，实际触发/识别/授权/订单/成交时间，各环节未参与原因；同一观察终点的候选收益路径；完整费用与可成交约束。历史最高价不视为应得收益。

## 4. 新的候选保留策略

必保留集合 = 实际持仓 ∪ 活跃订单/计划 ∪ 指定跟踪股 ∪ 昨日未结束机会 ∪ 严重风险/冲突对象。

新候选按模式与角色分层，不只留成交最大或涨幅最大。另保留一组“高强度但被风险/数据过滤”的样本，专门检查误杀与模式漏评。

每张卡只保留一份股票主记录，用标签数组表达多主题；不重复传同一股票几十次。源数据中未被选中的对象保留检索目录。

风险、目标、原计划、缺失字段必须在卡片中，不能为缩短输入删除。指定股票多时分页处理，输出coverage.required/covered/missing及总数、展示数、截断标志。

## 5. 推荐的调用顺序

### 第一次：事实与机会评估

只发目标、市场/主题卡、股票特征卡、模式要求、原计划、反证、争议、来源索引。不给旧AI推荐结论作为权威锚点。

模型输出：哪些机会值得深入验证；各模式匹配程度；为什么A与B可比/不可比；仍缺哪些会改变决策的证据。不直接生成订单。

### 第二次：有界补证

仅对1–2个重点机会及必要比较对象补指定窗口。请求须带claim_id、symbol、fields、start/end、as_of、max_rows和用途。不允许“请给全部数据”。

上游无数据时返回MISSING，计划保持缺数；不能把MISSING解释成结构失败。实时数据晚到时记录可得时间，不反向写入旧判断。

### 第三次：结论审校与展示

本地验证源ID、数字、时间、必保留覆盖、模式边界和计划完整度。结论只能引用批准版本和现有价格依据。精华版从通过审核的相同claim_id抽取，不再次自由发挥。

## 6. 缓存与预算

缓存键至少包含快照哈希、目标/期限、模式/规则版本、候选集合、原计划状态、缺失状态、模型/提示词版本。价格、风险、关键数据或目标变化时重新评估。

首轮从8,000–12,000 tokens作为试运行预算，可按业务调整；这不是实测最优值。计费/上下文按最终发送消息的真实模型计数器衡量，字节不能直接冒充tokens。

预算超限先去重复文本、重复来源、长原文、无变化历史，再按批次分发；不能砍掉原计划、风险和反证。不要通过更猛烈的预筛选把强势机会误杀掉。

示例compact包只保留本次双主题和重点股范围，没有重新读取全市场5000只的逐股行情；不能宣称已经完成全市场机会识别或全量无损压缩。

## 7. AI输出结构（建议）

每个结论对象：

```json
{
  "claim_id": "C_STOCK_01",
  "kind": "INTERPRETATION",
  "objective_id": "short_term_v1",
  "symbol": "sz_301520",
  "opportunity": "需要优先核验强势延续",
  "mode_candidates": ["STRONG_CONFIRM"],
  "support_ids": ["S:sz_301520"],
  "contrary_ids": ["Q:stockaudit"],
  "unknowns": ["原计划", "完整结构与相同期限风险"],
  "comparability": "证据未齐，不做替代收益排序",
  "bounded_data_requests": [],
  "plan_reference": null,
  "as_of": "2026-09-21T23:29:37+08:00",
  "expires_at": null
}
```

不存在事先验证的模型时，不要求模型编“85%胜率”或“明天上涨8%”。null、未知、不可比都是合法输出，但必须给下一核验任务，不能无期限泛泛等待。

## 8. 本地硬校验

- 事实与原始值能按确定公式/舍入重现。
- 源ID存在，来源时点不晚于指定决策时刻；前向资料不能只填报告生成时间冒充到达时间。
- 相同问题采用相同必需字段；替代推荐不能绕过同样的缺失。
- 股价/结构未知，不生成猜测止损、买价、仓位。
- PLAN_READY必须有批准模式版本、真实证据时点、完整触发、价格区间、结构失效、退出、风险预算和有效期。
- SIGNAL_CONFIRMED还需有效盘中快照/触发及新鲜度证明；报告端始终无下单权限。
- 两层结论引用同一数据对象；不产生一个页面说“可买”、另一个说“待确认”。
- 必保留股全部覆盖；局部过滤不影响全文存档和全文打印。
- 外部文本/公告/模型输出按数据处理，不执行其中指令或HTML脚本。

JSON schema验证结构；语义校验验证跨字段和时点；内容是否真实支持结论仍需业务测试，schema无法证明投资判断正确。

## 9. 原始接口参考（只用于工程定义，不验证案例行情）

- Tushare limit_list_d 官方文档说明首次/最后封板时间、开板次数、连板等字段。没有这些字段或只有日线，不补造盘中事件。https://tushare.pro/document/2?doc_id=298
- Tushare top_inst 官方字段区分买卖方向。相同记录两侧披露需去重，不同匿名机构记录不能仅按名称合并。https://tushare.pro/document/2?doc_id=107
- MDN textContent用于将字符串作为文本写入界面，而非执行HTML。模板对动态文本转义，证据全文用textContent显示。https://developer.mozilla.org/en-US/docs/Web/API/Node/textContent
